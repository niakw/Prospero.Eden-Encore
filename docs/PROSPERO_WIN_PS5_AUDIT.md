# Eden Encore ↔ prospero-win: PS5 runtime audit (2026-10-13, R416)

Scope: real native PS5 title on FW 13.60, FC27 (0100C49025D3E000), BOTW. This is a **cross-project technical comparison**, not a blanket Wine/DXVK transplant: Wine runs Windows PE->DXVK->Vulkan, whereas Eden translates Switch guest GPU commands->Eden Vulkan/RADV. Proven fixes in one stack may not be present in the other.

PS5 title credentials can trigger that silently. | **FIX IN R414**: a pinned, independently audited native Mesa `disk_cache_os.c` uses upstream `#if !defined(__PROSPERO__)`. Never release per-resource Vulkan/texture locks without a proof of lifetime, queue and ordering. |
| OS worker scheduling | FW12.02 Wine probe: 13 game CPU IDs `0..12`, default `SCHED_FIFO` priority ~700: a 14th busy worker of same priority waits indefinitely for CPU release; Wine patch 0882 opts into `SCHED_RR`. | **OPEN**. Avoid removing guest semaphores or deferring Vulkan resource destruction blindly. |

VK_FILTER_LINEAR)` from render framebuffer to target; this means small game renders do not necessarily create forbidden-sized WSI swapchains. | Texture/HUD corruption and flicker | Wine's pixel probes verify D3D frame readback, while Mesa display blit/lifecycle fixes address final presentation not the guest texture cache or descriptor semantics. | **UNPROVEN** whether WSI contributes to FC27 texture/HUD flicker. Eden #4473/#4477 was already shipped via immutable source backports BEFORE R408 (R411 corrected double application). Prioritize guest texture invalidation, Vulkan buffer ownership, DMA transfers, transient aliasing and descriptor lifetimes. | Quality / scaling | Direct VideoOut uses restricted framebuffer sizes; Pereira's WSI scales off-size with aspect preserved, whereas Encore already applies render-target scaling/FSR and another presentation blit if dimensions differ. | Check effective *guest resolution → scaling pass → present extent → physical output* before changing sharpness. ## Audit of current Encore code
- `headless/main.cpp`: configures `MESA_SHADER_CACHE_DIR`, disk-space-based `MESA_SHADER_CACHE_MAX_SIZE`. Those variables did **not** bypass prior `!__normal_user()` rejection.
- `vendor/encore-active/eden-vulkan/vk_pipeline_cache_cost.cpp`: `GetTotalPipelineWorkers()` takes live process/thread cpuset mask and preserves two logical slots for other background duties. Three secondary allowed CPUs means one builder in R410, not six.
- `headless/performance.cpp`: `PlaceSecondary()` currently calls `cpuset_setaffinity`, not `pthread_setschedparam`. No blanket RR policy has been shipped.
- `vendor/encore-active/eden-vulkan/vulkan_rasterizer.cpp`: `CurrentGraphicsPipeline()` occurs before paired guest buffer/texture cache lock in normal PrepareDraw; `PipelineCache` schedules shader workers. Do not claim Wine's global PE stream-gate bug exists identically here.
- `vendor/encore-active/eden-vulkan/vulkan_scheduler.cpp`: command chunks execute under `execution_mutex`, allowing queued work admission with separate `queue_mutex`; waiting inside that executor is relevant to pipeline first-use stutters. Any concurrency change requires queue/order/memory-lifetime testing.
- `vendor/encore-active/eden-vulkan/vulkan_present_manager.cpp`: direct `VK_FILTER_LINEAR` blit to swapchain when supported. Rendering at 1440p with 2160p display can therefore already scale without allocating a 1440p VideoOut swapchain.

## Evidence gate before claims or future merges
1. Qualify **R415 first**, not R413: one FC27 gaming session with existing settings, cache preserved between two starts. Inspect cache file creation and size, native `EDEN_PS5_SHADER_WORKERS` CPU mask and actual frame/wait witnesses. Do not require extra stress tests or repeated clearing of the shader cache.
2. If warm cache works but stutters persist on same scenes, categorize `gpu_dispatch_ms`, `dma_active_ms`, `puller_active_ms`, shader compile time, cache lock waits, and queue/present cadence. Correct the dominating path rather than guessing that faster output solves it.
3. Investigate on-console scheduler `pthread_getschedparam` for 5 hot + background workers **before** enabling RR. A policy/mask difference from Pereira's FW12.02 nullifies direct conclusions for FW13.60.
4. Stage only focused backports from current PS5 Mesa, with host WSI memory/release/scaling correctness tests and real PS5 compiler gate; preserve original vendored snapshots and native 4K present.
5. Keep one performance A/B variable per compiled build and do not conflate debug-log overhead with final FPS.

## R417 follow-up — firmware scheduling evidence (source-only)

R417 captures `EDEN_PS5_THREAD_SCHED` exactly once per actual Vulkan command worker and shader graphics/compute compilation thread. It records `pthread_getschedparam` policy (FIFO/RR/OTHER), effective priority, permitted CPU affinity and both API error codes. The change is read-only: it does not modify thread priorities, CPU placement, mutex scopes, the renderer, the shader-worker count, Mesa, or VideoOut.

The tracked prepared Vulkan files and `prepare-vulkan-port.py` source generator are updated together and qualified by a host fixture. Host tests establish source/wiring behavior only, not console performance. The real FW13.60 readback remains unknown until a hardware run; R415 is still the latest tested native archive, and R417 must NOT be presented as a FPS or graphics fix. Only contemplate explicit SCHED_RR A/B once the priority/mask measurements and hot-stage timings have been reviewed.
