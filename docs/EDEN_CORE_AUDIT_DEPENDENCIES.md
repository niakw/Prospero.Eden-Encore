**Technical scope:** guest CPU/HLE, JIT, GPU worker, Vulkan, memory coherency,

indexed graph rows cover known high-relevance paths; the completed register

flagged below. New source discoveries must be added rather than forgotten. Do not open
previously reviewed files without naming a concrete new source change or new
evidence. Other chats may change the branch concurrently; re-read HEAD before
any operation, and avoid unrelated files.

## Migration de sources et inventaire de sélection

Les lectures diagnostiques `IFile::Read` (F02), `IStorage::Read` (F03) et les trois opérations `IFileSystem` (F04)
sont des sources maintenues sous
`vendor/encore-active/eden-core/src/core/hle/service/filesystem/fsp/`,
sélectionnées uniquement en `EDEN_DEV_PROFILE`.
`tools/check-vendor-consolidation-debt.py` vérifie la parité du corps
C++ avec l'override généré auparavant et recense les sorties CMake dans
`docs/EDEN_OVERRIDE_MIGRATION_INVENTORY.md` : **47 sites restants**
après onze migrations (F02, F03, F04, N02, N03, H21, H22, F05, F06, F07 et F08). Un site à paramètres variables peut
produire plusieurs fichiers réels. Les ressources générées ne doivent
pas être confondues avec des overrides de code.

Le second inventaire compte 21 générateurs `write_derived()` dans les modules,
soit **68 sites au total**, mais n'inclut **pas** les cinq modules
`X01–X07` qui créent une sortie par `file(WRITE)` ou transforment
indirectement une variable-source. Ils sont suivis séparément dans
`docs/EDEN_OVERRIDE_MIGRATION_INVENTORY.md`, avec contrôle hôte de leur
présence et de leurs variables. Ces nombres sont des **sites et modules**, pas
un décompte exhaustif de fichiers C++ distincts.

Les chemins H18/H19/J14/J15 ont été catalogués pour éviter l'angle mort
entre thread `Runnable`, fibre sélectionnée, contexte restauré et
exécution JIT. La correction de propriété du verrou C32 est prouvée
par le test hôte précédent, **pas** par une exécution native invitée.
Une reprise du code invité après réveil reste un verrou de validation.

Les observateurs `N02` (`nvhost_ctrl`) et `N03`
(`BufferQueueProducer::DequeueBuffer`) sont désormais eux aussi des
unités C++ maintenues dans `vendor/encore-active/eden-core` pour
`EDEN_DEV_PROFILE`. La source épinglée reste sélectionnée hors DEV.
La parité avec l'ancienne génération et la politique de mesure silencieuse
sont exigées par les contrôles hôte. La progression réelle du jeu n'est
pas démontrée.

F05 et F06 cataloguent le runtime natif auparavant absent du graphe :
`Common::SetCurrentThreadName`, `Eden::Performance::RegisterWorker`,
`Common::FS::RemoveDirContentsRecursively` et
`Common::FS::IterateDirEntries`. Leurs unités de compilation sont
désormais maintenues dans `vendor/encore-active/eden-core/src/common/`
au lieu d'être produites par CMake. Les deux fichiers épinglés restent intacts.

F07 (`common/cpu_features.cpp`) et F08 (`common/fs/path_util.cpp`)
sont maintenant des sources maintenues dans `vendor/encore-active`,
avec sélection `common` et comparaison contre leur ancienne
transformation CMake. La preuve d'exécution native de leurs branches
de démarrage reste à acquérir.

F11 (`filesystem.cpp`) conserve dans une source maintenue l'injection de la racine firmware de `FileSystemController::CreateFactories`, sans validation matérielle annoncée.

F09 (`network.cpp`) reste une unité CMake générée pour le réveil du socket de contrôle hôte ; son protocole d'interruption doit rester inchangé. F10 (`network_interface.cpp`) est maintenant un fichier C++ maintenu avec ses trois sélections FreeBSD testées, sans preuve matérielle des interfaces effectivement retournées.

## Status is not success in game

- **HOST**: a *specific property* was exercised by a host test. A passing
  test may deliberately prove an unsafe behavior. It does NOT certify
  end-to-end console performance, correct emulation or freeze resolution.
- **SOURCE**: located and inspected in source, but no causal or end-to-end
  proof. Do not count it as solved.
- **OPEN**: concrete source-level question not resolved yet.
- **PARKED**: intentionally stopped. Deferred native bridge #187 stays OFF.

Priority **P0** means actual frozen gameplay/HUD/long-frame causality;
**P1** means correctness and native integration; **P2** means experimental
memory bridge safety. A HOST property can still have an unmet device gate.

1. October 15 FC27 session uses **Vulkan**. The 285.3 ms mutex wait is
   time lost by a guest CPU callback; the mutex *owner* is unknown.
   Texture-GC evictions were zero around frames 3300-3600. An ~980 ms

## How to update after each task

1. Read this register, the completed-audit index, the current branch HEAD, its linked evidence,
   then only the immediate caller/callee of the first relevant OPEN
   (or SOURCE with new evidence). Preserve concurrent work ownership.
2. Record an explicit hypothesis and a falsifiable check **before**
   changing behavior. If a previous hypothesis was disproved, do not
   reopen it without a code change or new observation.
3. After a narrow fix, update its row with the test, the *actual*
   completed CI URL/conclusion and the next still-unmet acceptance.
   A green test is not a green workflow; a green workflow is not
   a console game test.
4. When blocked or out of evidence, say so and leave the row open.
   Do not add another speculative test or pseudo-progress commit.
5. Keep source/derived file distinction. Console release/build
   only upon demonstrated benefit and authorization. No UI edits here.

The automated host register check validates paths, symbols, IDs,
dependency acyclicity and statuses, **not** behavior.
